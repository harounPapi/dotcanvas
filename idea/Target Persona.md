## Primary Wedge

The best initial wedge for DotCanvas is still a project-based professional working inside a structured corpus and responsible for producing a high-trust deliverable under time pressure.

The clearest first version of that wedge is:

`an audit, financial consulting, diligence, or evaluative analysis professional`

This user may not write code, but they do operate inside a very real project room:

- financial documents
- spreadsheets
- PDFs
- prior decks
- notes
- assumptions
- client comments
- draft outputs

Their job is to turn that material into a defensible artifact.

That makes them an excellent first user.

## The Bigger Truth

The product should not be defined only by this job title.

The deeper category is:

`someone working on a bounded, source-heavy project that must become a reliable deliverable`

That broader user definition includes:

- a student doing a thesis or PFE
- a researcher writing a paper
- a grant or proposal writer
- an investor reviewing startups
- a market researcher
- an entrepreneur writing a business plan

These people do not share one profession.

They share one project shape.

## Shared Project Shape

The users DotCanvas serves best usually have:

- a real corpus of material
- a meaningful output
- work that unfolds over time
- recurring context reload pain
- pressure to be right
- a need for traceability and support

This is the most important segmentation logic.

The wedge helps us start.

The project shape tells us what product we are really building.

## Why Financial And Evaluative Work Is The Best First Wedge

This wedge is especially strong because:

### 1. The corpus is obvious

The files are real, central, and unavoidable.

### 2. The deliverable is valuable

A better memo, assessment, or recommendation has clear economic value.

### 3. Trust matters a lot

Claims, numbers, and conclusions need grounding.

### 4. The continuity pain is severe

These users repeatedly reload the same project into their head.

### 5. The workflows repeat

Even if every case is different, the pattern recurs:

- ingest
- extract
- compare
- assess
- draft
- revise
- defend

That makes the wedge concrete without making the category too narrow.

## What The Primary User Is Really Trying To Do

This user is trying to:

- understand a project quickly
- keep track of what changed
- compare evidence
- preserve assumptions and findings
- draft a serious output
- stay grounded in source material
- resume interrupted work without starting over

The hard part is not only analysis.

It is continuity plus trust plus deliverable production.

## What They Secretly Want

This user does not really want "an AI agent."

They want something more practical:

- "Understand this project the way I do."
- "Stop making me reload context."
- "Help me move from source material to output."
- "Show me what supports each important claim."
- "Help me recover the state of this project fast."
- "Prepare me before I need to submit, present, or decide."

They want operational support for the project.

## Why General Chat Still Falls Short

General chat can be helpful in isolated moments, but it breaks down because:

- project state is fragile
- memory is weak
- files feel temporary
- outputs are not central
- workflows are not reusable
- it does not naturally support start, import, and resume

That is why the project room matters so much.

## Example Wedge Story

Sara is a senior analyst working on a financial review. Her folder contains audited statements, management accounts, prior decks, notes from calls, market reports, and a template for the final output.

Her challenge is not opening the files.

It is remembering what matters, spotting what changed, keeping assumptions straight, and turning all of that into a grounded recommendation.

A normal chat tool can answer isolated questions, but it does not really hold the project.

DotCanvas would help by turning the project into an active room with:

- a clear brief
- a map of the source corpus
- preserved project memory
- workstreams for different parts of the job
- grounded draft outputs
- a clear view of what should happen next

That is the real product value.

## Adjacent Users With The Same Shape

Once the wedge is working, adjacent users include:

- students doing a final-year project
- researchers writing papers
- proposal and grant writers
- VC analysts reviewing startups
- market researchers
- entrepreneurs building business plans

The language and artifact types differ.

The project structure does not differ very much.

## Product Implication

The product should be designed for the broader project shape, even if the first go-to-market wedge is narrower.

That means the core should support:

- project brief
- corpus map
- working memory
- workstreams
- outputs
- review state

And the wedge should mostly determine:

- starter playbooks
- example templates
- default vocabulary
- sample outputs

## Summary

The right first persona is not "all non-technical users."

The right first wedge is evaluative, document-heavy, trust-heavy project work such as audit or financial consulting.

But the real target user is broader:

`someone working on a bounded project with a real corpus, real stakes, and a real deliverable`

That is the user DotCanvas should be built for.
